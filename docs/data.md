# Data

Everything used to train and score the released models is in `data/`, 7.8 MB, with a SHA-256 manifest. Nothing here is private: see
[policy](policy.md).

```bash
wattson verify-data          # in the container;  or  uv run scripts/verify_data.py
```

## Layout

| Path | Rows | What it is |
|---|---|---|
| `data/tasks/train-pool-split-20261027` | 483 | training tasks: load-scale, line-rating and generator-dispatch fits, reports, tool trajectories |
| `data/tasks/train-pool-planning-split-20261029` | 563 | the above plus 80 worst-of-three-outages planning tasks; the v11 trajectories are built from this |
| `data/tasks/planning-train-20261029` | 80 | the planning tasks alone |
| `data/tasks/procedural-pool-20261024-v4` | 210 | pool used for the GRPO pilot |
| `data/suites/procedural-heldout-20261024-v4` | 90 | **primary endpoint**: held-out fits on networks no training row uses |
| `data/suites/smoke-validation-20-20261024-v2` | 20 | quick gate |
| `data/suites/judgement-20261024-v2` | 40 | reports and worst-outage choices |
| `data/suites/unsolvable-20261024-v2` | 28 | tasks naming an element that does not exist; the right answer is a refusal |
| `data/suites/planning-heldout-20261029` | 40 | worst-of-three-outages on two networks never trained, one wording never trained |
| `data/suites/derived-heldout-20261030` | 40 | sums, differences and means over several solver results, plus a minimum-voltage ranking |
| `data/suites/domain-held-out-20261020` | 306 | the original full held-out benchmark (older runs) |
| `data/suites/domain-stratified-100-20261024-v2` | 100 | a stratified sample of it (older runs) |
| `data/trajectories/20261029-v11-python` | 826 | Python-shell oracle trajectories (what Granite and the non-thinking Qwen were trained on) |
| `data/trajectories/20261029-v11-python-thinking` | 826 | the same with scripted reasoning (the thinking Qwen) |
| `data/trajectories/20261029-v11-plain` | 1029 | plain-tools trajectories (the matched control) |
| `data/trajectories/20261027-v9-*` | 743-947 | the earlier round (python, python-thinking, plain) |

Each directory has an `examples.jsonl` (or `trajectories.jsonl.gz`) and a `manifest.json` recording how it was built and its hash.

## Provenance

- **Networks:** the CSIRO Synthetic-NEM-2000-Bus case files (CC BY 4.0, fetched at a pinned commit and checksum-verified, never
  redistributed here) and cases bundled with pandapower (BSD-3-Clause).
- **Tasks:** generated by the scripts in `src/wattson/datasets/` from those networks, with fixed seeds. Targets and tolerances come from
  running the solver.
- **Trajectories:** written by a deterministic script (the "oracle") that runs the real solver and the real tool server. There is no
  model-generated text in them. The thinking variants contain scripted prose built from the prompt and earlier tool replies; a checker
  rejects any number in it that those do not contain.
- **Held-out means held out:** evaluation suites use networks and element lists that no training row uses, and the harness audits
  tasks against the training rows before it runs.

## Regenerating

`wattson.datasets.trajectories` rebuilds the trajectories from the task files (the smoke check does this for a handful). Solver
floating-point output depends on the library versions, which `uv.lock` pins; the shipped trajectories were built on Python 3.12 and
the pins are what makes the 3.14 environment reproduce their scores (the smoke check re-scores shipped model journals and requires
the counts to match).
