## Context for a reviewer unfamiliar with Wattson

Wattson is a local power-system study application. A small language model calls a
tool that runs actual calculations against network data; the application checks
answers by running the solver again. The newer standalone application is
`fungible-farm/wattson`. Its published PromptExecutionAU models were trained to use
a `run_python` tool backed by a solver. This branch now lives in that application's
canonical source tree; evidence recorded below was obtained in the legacy workspace
and on sm3lly, before the source was transplanted.

This change explores how to deliver that sort of application to a workstation
without installing every Python/Rust/Node utility into its operating system. A
container image packages executable software. A separate model image packages
weights. `just` names repeatable commands. `just-mcp` exposes selected commands as
agent tools. Podman starts the containers; only the host adapter needs access to
the container engine. The agent receives no engine socket.

The intended end state is connected preparation followed by disconnected execution:
`just install` lists and prepares dependencies; `just package` exports software,
model artifacts, source, checksums and locally generated SBOMs. That complete path
has **not** passed yet. Containers still require a working Linux kernel, rootless
Podman, user namespaces, cgroup delegation, shell, tar and checksum utilities.

The user prioritizes local, offline-capable tooling. Codex registration is no longer
a priority. Do not add a cloud model dependency or a b00t runtime dependency.

## Reviewer risks and scope limits

- This is an additive prototype in a legacy repository. The canonical Wattson
  integration and promotion path have not been agreed or applied.
- Several base images use readable tags rather than immutable digests. HF revisions
  and Python/npm/Rust dependencies are locked, but the complete OS supply chain is
  not reproducibly pinned. Do not claim bitwise reproducible builds.
- The CPU image is a downstream Candle-based server, not an official Candle image.
  Candle's inspected source had CPU/CUDA CI but no found official OCI-publishing
  workflow. No upstream Candle container proposal or PR has been submitted.
- The selected Qwen/Granite architectures, chat templates and tool-call parsers
  have not been exercised on this CPU server. Granite's supported-model status
  needs a direct loader check; do not infer it from a similarly named Granite family.
- `nemo-local` startup/readiness handling, all shared-node caps, fixed pod names,
  and model-specific result directories need review before operational use.
- The bundled MCP builder proves the MCP binary can rebuild from its cached SDK.
  It does not prove that every image can rebuild offline from source.
- Model staging, image layers and archive exports consume separate disk space.
  Image size is not a quota. CSI is a storage-driver interface; OCI image mounting
  needs actual Podman/CRI/Kubernetes support. k9s is only a cluster inspection UI.
- Shell/source/checksum/image-archive adapters are not an adversarial sandbox.
  A hash identifies content; it does not establish trusted approval or provenance
  by itself. Regex validation is not data authorization.
- Syft will produce a scan of actual image contents when packaging runs. Compiled
  Rust dependency coverage depends on metadata; an SBOM is not a vulnerability
  certification. The HF MCP npm build reported one moderate advisory; it has not
  been triaged or automatically rewritten during this shift.
- GenCost is NEMO's transcription of 2024-25 data, not an imported current CSIRO
  workbook. No optimizer, dbt, Parquet pipeline, ODBC/Oracle connector, Spark or
  marimo runtime is delivered by that task.
- `usage` may later improve CLI descriptions/completions. It is not the approval
  DSL. `mise` is not required for this image-pinned runtime.

The staging branches and logical commits are review artifacts; they have not been
merged into the default branch. No image, package, PR or issue has been published.
Generated
weights, OCI archives, caches, credentials and failed-run logs are not committed.
